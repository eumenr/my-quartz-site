## 一、協作原則與人工查核

- **工具入口**：[Gemini Notebook](https://notebook.google.com/?pli=1)
- **AI 協作角色**：參考臺北國稅局近 2 年新聞稿的行文風格與文章結構，協助發掘題材及起草。
- **人工查核重點**：法條、項次、適用要件、金額、裁罰倍數及發布內容，均須由承辦人確認。
- **來源引註用途**：AI 來源引註僅供回溯工作稿依據，不等於完成法規查核。

### 步驟三：設定本次起稿條件

請先確認下列事項，再貼入提示詞：

- 目標稅目與發布月份
- 預計產出篇數
- 預定題材或希望避開的近期主題
- 可使用的法規、函釋及案例條件
- 案例日期範圍及須特別提醒的事項

#### A. 無素材自行選題

```markdown
【本次設定】
- 目標稅目：[營業稅]
- 目標月份：[115年11月]
- 產出數量：[3篇]
- 案例日期範圍：[115年7-8月至115年9-10月]

【執行規則】
1. 標題與主題：
	- 選題基本條件：題材須符合本局業務範圍及本次指定稅目。
	- 選題時，應確認法規依據及宣導內容有可靠來源支持。
	- 如無足夠且可查證的題材，不得為湊足篇數而捏造法律依據或事實。
	- 優先避免每篇均集中於同一來源檔案。如無適當題材，不得為滿足來源分散而硬選不相關或不適用題材。
	- 「主題」係指主要稅務議題、適用對象及核心法令均高度相同之內容，不以標題文字不同即視為不同主題。
	- 不得採用臺北國稅局於 113年11月至115年11月 期間已發布之新聞稿標題或核心主題；判斷主題是否重複時，應比較其主要稅務議題、適用對象及核心法令，而非僅比較標題文字。
	- 各篇彼此之間的標題必須完全相異。
2. 結構與用詞：參考臺北國稅局近 2 年（即 114 年 2 月以後發布者）同類型新聞稿的段落結構、公務用語及法條引述口氣。不要寫聯絡人那一段。
3. 關於數字與日期：
	- 舉例之金額除依法條規定外，不得和原發布版本相同，盡量以整數為例（如 10 萬、200 萬等），且雙方約定金額（如房屋款與土地款）盡量不要相同。
	- 【重要】案例日期不得沿用原稿日期，原則上設定於目標月份前幾期；交易日期、進銷貨日期或發票期別，請使用「【案例日期範圍】」內的期間。法規規定的申報期別、法定期限及其他必要日期，不受此限制，不得擅自更改；目標月份之後尚未到來的期間或日期，不得寫成已發生、已開始或已屆至的事實。若無法確認正確表述，標示「【待人工查核】」。
	- 數字案例僅作為說明性假設，不得使讀者誤認為實際查獲案件；案例金額須可經人工重新計算驗證。
	- 假設案例應以「例如」或「假設」明確表達，不得寫成實際查獲案件。
4. 輸出限制：只輸出結果，嚴禁任何前言、說明或結語，但每篇開頭須明確標明引用參考來源。若未標記來源標號 [1]、[2]，視為不符合格式要求。
5. 【強制引註規範】內文凡論述法規條文、法律要件，或引用來源資料中的具體事實，該句句末「絕對必須」加上 Gemini Notebook 的來源標號（例如：[1]、[2]）。
	- AI 自行設定之假設案例、金額、日期及計算結果，不得虛構或強行附加來源標號。
	- 若內容無法由目前 Notebook 來源資料確認，不得自行製造來源標號。

【輸出格式】

### [標題]
- 引用來源：[檔案名稱，要附來源標號]（原發布年月：ＯＯ年ＯＯ月）
- 資料來源說明
	- [條列來源，如：加值型及非加值型營業稅法第1條、第3條、第28條及第51條第1項第1款。]

[內文]

---
[重複上述格式輸出第 2 篇、第 3 篇......直至【產出數量】]
```

#### B. 指定素材起稿

新聞稿素材表

一篇新聞稿填寫一張。先確認事實與可使用範圍，再交由 AI 起草。

```markdown
【新聞稿素材表】
1. 主題目的：[一句話說明要宣導什麼]
2. 法規依據：[相關法條/函釋]
3. 核心事實：[重點對象、期限、規定]
4. 案例與提醒：[假設情境與提醒事項]
```

> [!info]- 【新聞稿素材表】電郵釣魚信件
> ```markdown
> 【新聞稿素材表】
> 1. 主題目的：慎防假冒國稅局或電子發票整合服務平台之釣魚郵件，切勿點擊連結或洩漏個資。
> 2. 法規依據：財政部電子發票整合服務平台及國稅局官方防詐提醒。
> 3. 核心事實：不法份子假借「字軌審查未過」或「發票中獎」誘騙；官方絕不會要求以連結提供密碼或信用卡；可撥 165 專線查證。
> 4. 案例與提醒：營業人收到「字軌審查未過」郵件之處置；提醒恪守「不點擊、不下載、不輸入」原則。
> ```


> [!info]- 【新聞稿素材表】網路銷售公示資訊
> ```markdown
> 【新聞稿素材表】
> 1. 主題目的：提醒網路銷售營業人於網頁顯著位置標示名稱及統編。
> 2. 法規依據：營業稅法第28條、第46條、稅籍登記規則第4條。
> 3. 核心事實：辦妥稅籍即應標示公示資訊；網址/平台異動應於15日內辦理變更登記；限期未補正者依法處罰。
> 4. 案例與提醒：直播主甲辦妥稅籍但賣場未標統編；提醒營業人自主檢視官網及社群賣場；採假設案例。
> ```


> [!info]- 【新聞稿素材表】兼營營業人年度稅額調整
> ```markdown
> 【新聞稿素材表】
> 1. 主題目的：提醒兼營營業人於當年度最後一期（115年11-12月期）辦理全年度稅額調整。
> 2. 法規依據：營業稅法第36條、兼營營業人營業稅額計算辦法第7條。
> 3. 核心事實：採比例扣抵法者，應於116年1月15日前申報最後一期時彙總調整年度稅額，避免短繳受罰。
> 4. 案例與提醒：乙賣場兼售免稅農產品，申報時僅按當期扣抵卻漏做全年度調整；算式須可驗算。
> ```


```
【本次設定】
- 目標稅目：[營業稅]
- 目標月份：[115年11月]
- 產出數量：[1篇]
- 案例日期範圍：[115年7-8月至115年9-10月]

【新聞稿素材表】
1. 主題目的：[填入主題與宣導目的]
2. 法規依據：[填入法規、函釋或官方提醒]
3. 核心事實：[填入適用對象、期限、規定或宣導要點]
4. 案例與提醒：[填入假設情境、處理流程或提醒事項]

【執行規則】

1. 素材忠實性與標題規範：
	- 本稿之主題目的、法規依據、已確認事實、適用對象及宣導重點，以【新聞稿素材表】為準，不得自行新增、刪除或改變其核心法律意義。
	- 得依素材內容設計合理的假設案例，但案例不得改變法規適用要件，亦不得將假設情境寫成實際查獲案件。
	- 標題應依新聞稿目的及素材內容轉化，參考臺北國稅局近 2 年同類型新聞稿的公務用語與風格。
	- 與本局既有新聞稿之比對，應以起稿當日已發布的稿件為準；不得僅更換標題文字而沿用高度相似的核心主題。
2. 結構與公務用語：
	- 參考臺北國稅局近 2 年（114 年 2 月以後）同類型新聞稿之 3～4 段式段落結構（1.重點宣導、2.法令細節/要件、3.假設案例/情境處理、4.叮嚀與呼籲）、公務用語及語氣。
	- 內文開頭統一為「財政部臺北國稅局表示……」，嚴禁撰寫新聞聯絡人、聯絡電話及分機等資訊。
3. 日期、數字與情境案例：
	- 日期限制：假設案例中的交易日期、發票期別或通知收到日期，必須使用【本次設定】之「案例日期範圍」（如：115年7-8月期、115年9月間等），不得沿用舊稿日期或目標月份。法規規定的申報期別、法定期限及其他必要日期，不受此限制，不得擅自更改；目標月份之後尚未到來的期間或日期，不得寫成已發生、已開始或已屆至的事實。若無法確認正確表述，標示「【待人工查核】」。
	- 依素材性質呈現案例：若素材屬「補稅/課稅/稅額計算案件」，案例金額請使用清楚整數（如 10 萬、200 萬等），且計算邏輯須可人工驗算；若素材屬「行政宣導/防詐提醒/系統升級」等無稅額計算之題材，案例請採情境模擬（如：營業人接獲通知之處置流程）表達，切勿強行編造補稅金額或算式。
	- 假設案例應以「例如」或「假設」明確標示，不得寫成實際查獲案件。
	- 素材未提供或無法確認之細節，標示「【待人工查核】」，嚴禁自行捏造。
4. 強制引註與來源標註規範：
	- 內文凡論述法規條文、法律要件，或引用 Gemini Notebook 來源資料中之具體事實，該句句末「必須」加上 Gemini Notebook 的來源標號（例如：[1]、[2]）。
	- 若該事實純屬使用者於【新聞稿素材表】提供、且 Gemini Notebook 既有檔案中查無對應依據，請勿虛構來源標號。
	- AI 自行設定之假設案例、情境模擬及日期，不得附加來源標號。
5. 純粹依據【新聞稿素材表】提供的內容，若沒有對應的 Gemini Notebook 來源，不得強行加註來源標號；但仍應依素材表列明的法規或官方資料，填寫「資料來源說明」，並由承辦人確認其正確性。

### 步驟四：實用提問 Prompt

> [!tip]
> 複製下方框內完整文字，修改篇數和月份後，直接貼入 Gemini Notebook 聊天框發問。
> 1. 按長官要求，語氣結構等應參採 114年2月以後發布之新聞稿。
> 2. 自行調整後建議存入自己的 [HackMD](https://hackmd.io/login) 以供下次使用。


**需要修正時，依問題類型選擇下列指令：**

#### 1. 標題／主題重選

```markdown
請重新檢查本稿標題及核心主題是否與「臺北國稅局」近2年新聞稿重複或高度相似。

注意：
1. 「主題」不得僅以標題文字不同判定，應比較主要稅務議題、適用對象及核心法令。
2. 如與既有稿件高度相似，請重新參考其他區局新聞稿來源尋找不同題材。
3. 不得只更換標題而保留相同核心主題。
4. 不得為了強制分散來源而選擇與營業稅無關或不適合本局發布的題材。
5. 重新產出完整新聞稿，不要說明修改過程。
```

#### 2. 臺北國稅局語氣/結構調整

```markdown
請重新檢視本稿，參考臺北國稅局114年2月以後發布之同類型新聞稿，調整段落結構、公務用語、敘事方式及法條引述口氣。

要求：
1. 保留本稿原有稅務議題及法律邏輯。
2. 不得直接複製參考新聞稿的句子、案例或數字。
3. 避免口語化、教科書式或明顯 AI 生成語氣。
4. 不要加入臺北國稅局新聞稿通常沒有的說明性小標題。
5. 不要寫聯絡人段落。
6. 僅輸出修改後的完整新聞稿。
```

#### 3. 法規及來源引註檢查

```markdown
請重新檢查本稿所有法規、法條、項次、款次、適用要件及具體法規事實的引用。

請逐句檢查：
1. 該句內容是否能由目前 Gemini Notebook 已載入的來源支持。
2. 法規名稱、條號、項次、款次及引用內容是否一致。
3. 是否存在來源不足、來源不明、內容矛盾或無法確認的情形。
4. 有可核對的 Gemini Notebook 來源時，於相應句末加註正確來源標號 [1]、[2]；不得虛構來源標號。
5. 純粹依據「新聞稿素材表」提供的內容，若沒有對應的 Gemini Notebook 來源，不得強行加註來源標號。
6. 不得僅因舊新聞稿曾引用某條法規，就認定該條文目前仍有效或適用。
7. 無法確認的內容，請標示「【待人工查核】」，不得自行猜測或補寫。

請注意：來源標號僅供回溯查核，不代表法規現行有效、法律解釋正確或適用要件已經確認。

檢查完成後，重新輸出完整新聞稿。
```

#### 4. 金額/日期/期別檢查

```markdown
請重新檢查本稿所有案例中的金額、日期、發票期別、稅額及計算邏輯。

要求：
1. 案例日期不得沿用原新聞稿日期。
2. 案例日期依原Prompt規則設定於目標月份前幾期，不得自行改成目標月份。
3. 案例金額原則上使用清楚的整數。
4. 除依法規固定規定之金額外，不得直接沿用原新聞稿案例金額。
5. 同一案例中不同標的之約定金額應避免相同。
6. 涉及營業稅計算時，請依該案例適用之稅率及計算方式重新列式驗算含稅、未稅、銷項稅額及應納稅額之邏輯。
7. 發票期別須與案例日期相互一致。
8. 若計算結果或日期邏輯無法確認，請標示「【待人工查核】」，不得自行猜測。

檢查完成後，重新輸出完整新聞稿。
```

#### 5. 最終規則重整

```markdown
請依照本次最初提供的完整Prompt規則，重新檢查目前新聞稿。

請特別檢查：
- 目標稅目是否為營業稅
- 目標月份是否正確
- 產出篇數是否正確
- 各篇標題是否完全不同
- 各篇核心主題是否高度重複
- 是否與臺北國稅局近2年新聞稿標題或主題重複
- 引用來源是否確實支持所引用的內容
- 是否誤帶入其他區局之機關名稱、地區、承辦單位或聯絡資訊
- 是否沿用舊稿日期
- 是否沿用舊稿案例金額
- 案例日期及發票期別是否符合本次Prompt規定
- 是否有「【待人工查核】」標示需要注意的內容
- 輸出格式是否符合指定Markdown格式

如發現問題，直接修正；無法確認的內容標示「【待人工查核】」。
最後僅輸出修正後的完整新聞稿，不要輸出檢查報告、修改說明或前言。
```
